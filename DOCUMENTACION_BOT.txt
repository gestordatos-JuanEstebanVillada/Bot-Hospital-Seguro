1. ¿QUÉ HACE ESTE BOT EN UNA FRASE?
================================================================================

Todos los días (o bajo demanda) consulta en Oracle las tareas en estado
Planeado (PL), decide si HOY corresponde enviar un recordatorio según reglas
de calendario e historial, envía correos HTML por Gmail OAuth2 al responsable
mapeado en correosUsuarios.js, y guarda cada envío exitoso en la tabla
"HS-historial_correos_bot". Además expone un panel web para ver el historial
y hacer login contra intranet_usuarios.

──────────────────────────────────────────────────────────────────────────────

  · Ignora reglas de fecha.

Para probar TODAS las filas (muchos correos):

──────────────────────────────────────────────────────────────────────────────
C) ENVÍO REAL SEGÚN REGLAS DE FECHA (producción manual)
──────────────────────────────────────────────────────────────────────────────
  npm run run-once

  · Una sola ejecución y termina.
  · Usa correosUsuarios.js para destinatarios.
  · Solo envía si HOY cumple algún escenario (ver sección 8).
  · Guarda historial tras cada envío exitoso.

──────────────────────────────────────────────────────────────────────────────
D) BOT AUTOMÁTICO + PANEL WEB
──────────────────────────────────────────────────────────────────────────────
  npm start

  · Cron todos los días 8:00 AM (America/Bogota).
  · Panel: http://localhost:2134/admin/login  (o ADMIN_PORT)
  · Proceso queda corriendo (no es un “envío inmediato”; espera las 8AM).

Flags opcionales en index.js:
  node src/index.js --once       Igual que npm run run-once
  node src/index.js --no-cron    Solo panel web
  node src/index.js --no-admin   Solo cron, sin panel

6. FLUJO COMPLETO PASO A PASO (PRODUCCIÓN)
================================================================================

Archivo principal del job: src/services/enviarRecordatorios.js

  1. initOraclePool() ya corrió en index.js (o testEnvio.js).
  2. getPool().getConnection() — una conexión por ejecución del job.
  3. Ejecuta SQL_TAREAS_PLANEADAS (src/queries/tareasPlaneadas.js).
     Trae filas con ultima_fecha_envio del historial (LEFT JOIN).
  4. crearTransporter() — OAuth2 Gmail (src/email/transporter.js).
  5. Por cada fila:
       a) usuario → correosUsuarios (minúsculas).
       b) resolverDestino: producción usa mapa; prueba usa CORREO_PRUEBA.
       c) resolverEscenarioEnvio(fecha_compromiso, ultima_fecha_envio)
          (src/utils/fechas.js).
       d) Si escenario = null → omitir fila ese día.
       e) buildAsunto + buildHtmlCorreo (src/email/template.js).
       f) transporter.sendMail().
       g) registrarEnvioExitoso → tabla HS-historial_correos_bot.
  6. connection.close() — devuelve conexión al pool.

8. REGLAS DE FECHAS Y ESCENARIOS DE CORREO
================================================================================

Archivo lógica: src/utils/fechas.js
Función: resolverEscenarioEnvio(fechaCompromiso, ultimaFechaEnvio)
Zona: America/Bogota, comparación por día (sin hora).

─── A) Tarea NO atrasada crónicamente ───
    (aún no pasó 1 mes calendario completo desde vencimiento)

    | Escenario              | Condición                          |
    |------------------------|------------------------------------|
    | CINCO_DIAS_ANTES       | Faltan exactamente 5 días          |
    | UN_DIA_ANTES           | Falta exactamente 1 día (mañana)   |
    | QUINCE_DIAS_DESPUES    | Pasaron exactamente 15 días        |
    | (ninguno)              | Cualquier otro día → no envía      |

─── B) Tarea atrasada crónicamente ───
    (vencida ≥ 1 mes calendario: hoy >= fecha_compromiso + 1 mes)

    | Escenario                      | Condición                           |
    |--------------------------------|-------------------------------------|
    | RECORDATORIO_INICIAL_ATRASADO  | ultima_fecha_envio NULL → envía HOY |
    |                                | (una sola vez “de choque”)          |
    | RECORDATORIO_MENSUAL_VENCIDO     | ultima_fecha_envio existe Y         |
    |                                | hoy = ultima_fecha_envio + 1 mes    |
    | (ninguno)                      | Entre medias → no envía ese día     |

    El mensual recurrente NO se calcula desde fecha_compromiso original,
    sino desde la última fecha registrada en el historial.

Asuntos (template.js):
  · CINCO_DIAS_ANTES:     ¡Aviso! Tarea por vencer en 5 días - Evento #...
  · UN_DIA_ANTES:         ¡Urgente! Tarea vence mañana - Evento #...
  · QUINCE_DIAS_DESPUES:  ¡Alerta! Tarea vencida hace 15 días - Evento #...
  · INICIAL_ATRASADO:     ¡Aviso Urgente! Tarea con atraso acumulado crítico...
  · MENSUAL_VENCIDO:      Recordatorio Mensual: Tarea aún sin gestionar...

Estado en correo: PL → "Planeado" (src/utils/estado.js)

18. PUESTA EN PRODUCCIÓN Y SOLUCIÓN DE PROBLEMAS
================================================================================

Checklist:
  [ ] .env completo (Oracle, Gmail, SESSION_SECRET)
  [ ] Tabla "HS-historial_correos_bot" creada (+ columna item si aplica)
  [ ] correosUsuarios.js actualizado
  [ ] npm test en verde
  [ ] npm run test-emails:una-fila → llega a CORREO_PRUEBA
  [ ] npm start o servicio Windows/PM2 para cron + panel

Problemas frecuentes:

  "No envía con run-once"
    → Normal si ninguna fila cumple escenario HOY. Ver sección 8.

  "Sin correo configurado"
    → Agregar usuario en correosUsuarios.js.

  "CORREO_PRUEBA obligatorio"
    → Definir en .env antes de test-emails.

  Error OAuth invalid_grant
    → Renovar GMAIL_REFRESH_TOKEN.

  Error Oracle ORA-00942
    → Crear tabla HS-historial_correos_bot o agregar columna item.

  Error login admin
    → Verificar intranet_usuarios y SESSION_SECRET.

  Correos a spam
    → Cuenta institucional, SPF/DKIM del dominio.
